# boretube v2 — P2 plan (TV Guard)

Spec: `docs/superpowers/specs/2026-10-28-boretube-v2-design.md` §6–§8. P1 is done and was tested on the real phone and TV.

The order was agreed with the user:

1. agent + install/repair
2. Break / Mute-for-N enforced on the TV
3. watchdog
4. rules
5. phone switch-over

The user explicitly asked that we can always **restore the original state**, especially after system-update problems. This is a first-class feature (§R below).

## Facts from P1 that the agent must respect

- The TV ignores absolute volume set and explicit `media_session --adj mute/unmute`. Only key events work, and `KEYCODE_VOLUME_MUTE` is a toggle. The agent drives sound with `input keyevent` via self-ADB and reads it from `dumpsys audio` STREAM_MUSIC.
  - Agent spike: does `AudioManager.adjustStreamVolume` from an app context work? If it does, prefer it. If not, use the ADB key path.
- Legacy ADB `:5555` persists across reboots (`persist.adb.tcp.port=5555`). Wait at least 60 s after a package-state change before any reboot.
- Never disable `setupwraith` (it owns the saved Wi-Fi), `launcherx` (remote app buttons and voice), or `dreamx` (Google Photos screensaver).
- `com.google.android.tts` known-good version is `googletts.google-speech-apk_20251028.02_p2.827711934`. The Play build `20260928` crashes with SIGILL.
- The launcher is `com.gathin.tvhome` with its `HomeKeyService` accessibility helper. The agent must **not** add an accessibility service, because a key-filtering service breaks volume-hold repeat.

## Agent ↔ phone contract (v1)

- **Transport.** HTTP/1.1 + JSON on TCP `:8790`, LAN only. It is announced via NsdManager as `_boretube._tcp`, TXT `id=<agentId>`, `ver=<versionName>`, `api=1`.
- **Auth.** `Authorization: Bearer <token>`.
  - On first start the agent creates a random 32-byte hex token and stores it at `/sdcard/Android/data/com.rakesh.boretube.agent/files/token`. Only ADB/shell can read it.
  - The phone reads it once over ADB: `cat <path>`.
  - A missing or wrong token gets 401.
- **Ids.** `agentId` is random and persisted. It is also written to `files/agent_id`.

**Endpoints:**

- `GET /v1/status` returns:
  - `agentId`, `version`, `api`
  - `uptimeSec`, `bootCount`
  - `selfAdb`: `ok|needsApproval|unavailable`
  - `mode`: `normal|safe|paused`
  - `now`: `{foreground, volume, min, max, muted}`
  - `activeRulesVersion`
  - `break`: `{active, endsAt}`
  - `health`: `[{id, status, detail}]`
  - `buildFingerprint`, `buildChangedSinceApproval` (bool)
  - `clockSkewWarn`
- `GET /v1/rules` returns the rules document. `PUT /v1/rules` takes the whole document; `version` must equal the current one, else 409 with the current document.
- `POST /v1/action` with `{action: mute|unmute|stop|volume|bore|restore|break|endBreak|muteFor, value?, minutes?}` returns `{ok, detail}`.
  - `break` and `muteFor` are enforced on the TV until `endsAt`, with no phone needed.
  - `restore` ends breaks and timed mutes and unmutes.
- `GET /v1/journal?since=<epochMs>` returns `[{time, op, target, before, after, ok, source: agent|watchdog|rule}]`. It's a ring buffer of 1000 entries.
- `POST /v1/mode` with `{mode: normal|paused|safe}`.
  - **Paused**: enforce nothing and run no watchdog writes.
  - **Safe**: enforce nothing, run no watchdog writes, and report only.
- `POST /v1/approveBuild`: the parent approves the current build fingerprint for watchdog writes.
- `POST /v1/profile` takes the device-profile JSON the watchdog uses (cleanup list, neverTouch, knownGood, stockYouTube). The phone pushes it on install and again on change.
- `POST /v1/restore` with `{target: "undoBoretube"|"stock"}`. It runs the restore plan (§R) on the TV, journals each step, then switches the agent to **paused**.

**Rules document:**

```json
{
  "version": 3,
  "updatedBy": "phone name",
  "updatedAt": "ISO",
  "style": "sneaky|explicit",
  "allowedApps": {
    "mode": "off|allowlist|blocklist",
    "packages": ["org.smarttube.stable"]
  },
  "volumeLimit": {"maxPercent": 30, "enabled": true},
  "alwaysMute": false,
  "tvTime": {
    "schedule": [{"days": [1, 2, 3, 4, 5], "from": "21:00", "to": "07:00"}],
    "dailyLimitMin": 0
  },
  "overrides": [
    {"kind": "allowApp|muteUntil|breakUntil", "pkg": "...", "until": "ISO"}
  ],
  "stockYouTubeAllowed": false
}
```

## Agent architecture (`boretube-agent/`, Kotlin, Android TV)

- **Package and SDK.** `com.rakesh.boretube.agent`, minSdk 26, targetSdk 34. No LEANBACK_LAUNCHER tile.
- **Components:**
  - `GuardService`: a foreground service with a low-priority notification. Started by `BootReceiver` (BOOT_COMPLETED, LOCKED_BOOT_COMPLETED, MY_PACKAGE_REPLACED), and by the phone via `am start-foreground-service`.
  - `PackageReceiver`: PACKAGE_ADDED/REPLACED/CHANGED triggers the watchdog.
- **Pure-Kotlin core** with no Android imports, unit-tested on the JVM:
  - `RuleEngine(rules, now, observed) → List<Decision>`
  - `BreakState`
  - `TvTime` accounting
  - the `Watchdog` planner (profile + observed package states → planned ops)
  - `SafetyGuard`
- **Android adapters:**
  - `ForegroundWatcher`: UsageStatsManager events, polled at 1 s.
  - `SoundController`: AudioManager first if the spike proves it works, else ADB keys.
  - `Shell`: dadb to `localhost:5555` with the agent's own key. The phone guides the one-time "Allow".
  - `Overlay`: an explicit card via SYSTEM_ALERT_WINDOW.
  - `HttpServer`: a small ServerSocket-based HTTP/JSON server; no heavy dependency.
  - `NsdAnnouncer`.
- **Enforcement loop** (1 s tick and events):
  - compute decisions
  - sneaky: force-stop the blocked app + HOME, mute/clamp
  - explicit: show the card, then HOME
  - re-assert mute or clamp within about 200 ms of a volume change (ContentObserver on volume settings plus the tick)
- **Permissions granted by the phone over ADB:** `appops set com.rakesh.boretube.agent GET_USAGE_STATS allow`, `appops set … SYSTEM_ALERT_WINDOW allow`, `pm grant … android.permission.WRITE_SECURE_SETTINGS`, and the POST_NOTIFICATIONS grant.

## §R Safety and restore (user requirement)

- **Build-change gate.** The agent records the approved `ro.build.fingerprint`.
  - After an OTA the fingerprint changes. The watchdog then still runs **low-risk ops** (remove stock YouTube, speech rollback to the factory build).
  - It holds **cleanup re-apply** as "pending approval" until the parent taps Approve on the phone.
- **Boot-loop guard.** If the TV boots 3 or more times within 15 min, the agent enters **safe mode**: no writes, no enforcement, only reporting.
- **Kill switches.** On the phone: Pause TV Guard, Safe mode, Uninstall TV Guard (over ADB).
  - If the agent is unreachable, the phone can still do everything over ADB.
  - Uninstalling the agent leaves the TV fully working.
- **Baseline snapshot.** On first ADB connect to a TV, the phone stores a **baseline** per TV:
  - `pm list packages -d` and `-u` state
  - stock YouTube state
  - the tts version
  - `enabled_accessibility_services`, `accessibility_enabled`
  - the HOME resolution
  - the build fingerprint
  - the agent's presence

  It is exportable as JSON.
- **Restore targets** (phone, TV tab → Settings → "Restore TV"). Each lists its exact steps first and journals every step:
  - **Undo boretube:** revert boretube's own journaled changes (re-enable what it disabled, restore stock YouTube if boretube removed it) and remove the agent.
  - **Back to stock:** re-enable every package in the profile's cleanup and extras lists, install-existing stock YouTube and YouTube Music, enable speech updates (no action; let Play update), and remove the agent.
    - It leaves the custom launcher alone unless the "also remove custom launcher helper" box is ticked, which clears the accessibility list entry and resolves HOME back to launcherx.
    - It never touches the never-touch list.
- **Restore without the agent.** Each restore runs from the phone over ADB, so it doesn't need the agent. The agent's own `/v1/restore` is a convenience.
- **Reboot discipline.** If a restore recommends a reboot, it waits 60 s first.

## Phone side

- **Agent bundle.** `assets/agent/boretube-agent.apk` with its SHA-256 and signing cert recorded in `assets/agent/manifest.json`. Before install, the phone verifies the hash.
- **Install / Repair flow.** Push and `pm install -r`, grant permissions, start the service, read the token, guide the self-ADB "Allow" ("Look at the TV" step), push the profile, then verify with `/v1/status`.
  - **Repair** covers four cases: the agent is disabled (`pm enable`), missing (reinstall), not running (start it), or the token has changed (re-read it).
- **AgentClient** (Dart) implements the contract with timeouts and 401/409 handling.
- **Status pill:**
  - 🟢 TV Guard on
  - 🟡 limited (self-ADB not approved) or paused
  - 🔴 down
  - 🛟 safe mode
  - ☕ break
- **Now tab.** With the agent present, quick actions go via `/v1/action` (ADB stays the fallback). Break and Mute-for-N become agent-enforced, and the banner shows "Enforced by TV".
- **Rules tab.** Editors for allowed apps (picked from TvOps.listApps), volume limit, TV time (schedule rows + daily limit), and the style switch. Temporary overrides: "Allow YouTube tonight" and "Muted for 30 min".
- **TV tab.**
  - Health merges the agent's health.
  - The agent card shows version, mode, self-ADB, Pause/Safe/Uninstall, and Approve-build when one is pending.
  - Activity merges the agent journal, with "While you were away" grouping.
  - Settings → Restore TV.
- Baseline capture on first connect.

## Testing

- **Agent JVM unit tests:** RuleEngine (allow/block, schedule across midnight, daily limit, overrides expiry, style), BreakState, Watchdog planner (OTA gate, never-touch, known-good), SafetyGuard (boot loop), JSON contract round trips, HTTP auth/409.
- **Agent on-TV smoke test** (scripted from the laptop over ADB, with the user's approval): install, permissions, status 200, token 401/200, break enforcement (unmute with a remote keyevent → re-muted under 1 s), blocked app closed, watchdog dry-run report, restore dry-run.
- **Phone tests:** AgentClient against a fake HTTP server, install flow with a fake ADB, Rules editor widget tests, restore planner unit tests (exact command list per target, never-touch respected), baseline capture/parse.
- **Live opt-in:** read-only status from the real agent.
- **Gates:** `flutter analyze` 0 issues and `./gradlew test` green.
